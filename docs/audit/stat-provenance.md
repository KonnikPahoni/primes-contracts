# Stat provenance

Generated by `node tools/stat-provenance.mjs` at commit `e28f1ce33` (2026-11-23).

`CLAUDE.md` rule 3 and `CONCEPT.md` §9.1: **every number the UI shows must map to a public
get-method**, and every parameter to `shared/params.json`. This file walks the chain that
claim rests on and reports every link that does not close.

```
webapp/src/api/*      ->  the read-proxy route it fetches
read-proxy route      ->  the chainClient function(s) that route calls
chainClient function  ->  the get-method named in its `provenanceBase`
```

## What this proves, and what it does not

It proves the **supply** side: that each route the webapp fetches resolves to named
get-methods. It cannot prove the **demand** side — it cannot see a number a component
renders, because rendering is JSX over values whose provenance is not in the identifier.
A component that fetches nothing and prints `1.02 GRAM` is invisible to the chain walk;
§5 below is the partial cover for that (literal scan), and a human read is the rest.
**Do not read a clean run here as "§9.1 is satisfied".** Read it as "no route serves a
number it cannot attribute".
